# Security policy

## Supported version

Only the current `main` branch is supported.

## Report privately

Do not open a public issue for a vulnerability, credential, personal information, customer information, confidential material, or an accidentally published source file.

Use the repository host's private vulnerability-reporting or security-advisory feature when it is available. If it is unavailable, contact the maintainer through an existing private channel. Include the repository URL, commit, affected path, impact, and the minimum reproduction detail needed to investigate. Do not copy a live credential or confidential document into the report.

## Public-data exposure

If private material is found in current files or history, report the path and commit privately. Do not quote, repost, fork, or otherwise redistribute the material. History cleanup must cover branches, tags, pull-request references, forks, and cached views.

## Release boundary

The public Core may contain reusable methods, tooling, and public-source examples. It must not contain live project work, customer data, credentials, personal operating state, restricted sources, confidential product information, or roadmap content.
